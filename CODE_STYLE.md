# Стиль кода WARPOINT

Форматирование задаёт корневой файл .prettierrc.json: два пробела, одинарные кавычки в JavaScript, двойные в JSX, ширина строки 100 символов. JSX должен показывать структуру страницы; несколько крупных элементов в одну строку не записываем.

## Компоненты и данные

- Страница в app получает данные города, проверяет доступность и задаёт metadata.
- Общая оболочка, первый экран, карточка, окно подробностей и интерактивный список — отдельные компоненты в components/site.
- use client нужен компоненту с состоянием, эффектами или обработчиками. Статическую страницу целиком клиентской не делаем.
- Тексты, параметры фильтров, тарифы и содержимое статей храним в lib. Подтверждённые изображения и цены сохраняем; новые данные не придумываем.
- Ключи карточек берём из стабильного id, а не из позиции в списке.

## BEM и SCSS

- Используем block, block__element, block--modifier и block__element--modifier.
- Стилизуем заголовок, текст, изображение и кнопку по классу элемента. Селекторы вида .card h2 или .page p для новых блоков не добавляем.
- Состояния оформляем модификаторами --active, --open, --disabled. Атрибуты aria-expanded, aria-current и aria-pressed продолжают описывать доступность.
- У каждого блока или связанной группы карточек свой SCSS-модуль. Внутри блока используем &__element и &--modifier. Не объединяем стили разных страниц в new-pages.scss.
- Исключения — общие элементы HTML, технические состояния страницы (например html:has(dialog[open])) и редакционный контент статей. Внутри article-detail__content и article-preview__body заголовки, абзацы, списки, таблицы, ссылки, изображения и цитаты оформляем по тегам без классов. Используем ограниченные контейнером селекторы с :where(), чтобы они не перебивали вложенные компоненты. BEM сохраняем у оболочки, оглавления, метаданных, блока заявки, кнопок и обёртки прокрутки таблицы; id разделов нужны для якорей.

## Проверка

Перед завершением изменений новых страниц:

```sh
npm run format:pages
npm run format:pages:check
npm run build
```

Проверяем изменённые страницы на широком и мобильном экранах: фильтры, вкладки, модальные окна, FAQ, навигацию по статье и отсутствие горизонтальной прокрутки. При рефакторинге сохраняем тексты, цены, изображения, SEO и текущие сценарии бронирования.
