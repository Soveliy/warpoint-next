# Как продолжать работу над сайтом WARPOINT

## 1. Что считать исходным кодом

Рабочий сайт находится в самостоятельной папке `D:\projects\warpoint-next`. Классическая вёрстка на Vite осталась в соседней папке `D:\projects\warpoint`. Новые страницы, правки текста и стилей вносите в Next.js; копировать готовый HTML из старого проекта не требуется.

Сейчас доступны `/`, `/games/`, `/tariffs/`, `/articles/`, `/legal/privacy/`, `/events/birthday/`, `/events/corporate/`, `/events/graduation/` и `/locations/`. Все эти маршруты рендерятся сервером для города, определённого по домену запроса.

## 2. Локальный запуск и остановка

Из папки Next.js-проекта в PowerShell:

```powershell
cd D:\projects\warpoint-next
npm install
npm run dev
```

Сайт откроется на `http://localhost:3002/`. Остановить его можно `Ctrl+C` в том же терминале. Для проверки собранной версии вместо dev-режима:

```powershell
npm run build
npm run start
```

Команды `npm run dev`, `build` и `start` в этой папке запускают Next.js. В соседнем проекте те же имена команд запускают классическую Vite-сборку. Перед запуском убедитесь, что порт 3002 свободен.

Для просмотра другого города локально задайте домен из ERP перед запуском:

```powershell
$env:PREVIEW_SITE_HOST = 'kursk.warpoint.ru'
npm run dev
```

После проверки удалите переменную текущего терминала: `Remove-Item Env:PREVIEW_SITE_HOST`. Приложению нужен доступ к ERP `https://gserver.warpoint.ru/api/site/v2/countries`; другой адрес можно передать через `ERP_COUNTRIES_URL`.

## 3. Где делать изменения

| Порядок секций главной и мероприятий                                       | `components/site/HomeSections.jsx`, `BirthdaySections.jsx`, `CorporateSections.jsx`, `GraduationSections.jsx`              |

Новые повторяемые блоки оформляйте отдельными React-компонентами и БЭМ-классами. Не редактируйте файлы в `.next/`, `dist/` и `node_modules/`. Перед изменением API Next.js прочитайте соответствующую локальную документацию в `node_modules/next/dist/docs/`, как требует `AGENTS.md`.

## 4. Данные ERP, города и SEO

`lib/site.js` получает список стран и городов на сервере, сопоставляет `Host` с `links.site_url`, подставляет арены и формирует canonical для текущего домена. Страницы без найденного домена возвращают 404. Ответ ERP кешируется на 300 секунд; время меняется через `ERP_REVALIDATE_SECONDS`.

Для каждого нового публичного маршрута добавляйте `generateMetadata()` с `metadataFor(...)`, проверяйте canonical на нескольких доменах и включайте маршрут в `app/sitemap.xml/route.js`. Контент, который должен индексироваться, выводите в серверном HTML; фильтры и модалки могут оставаться клиентскими.

Сейчас ERP-ответ не содержит тарифов для всех городов. Статические цены из макетов показываются только для Екатеринбурга, для остальных городов — «По запросу». Не копируйте екатеринбургские цены на другие поддомены без подтверждённых данных. ERP также отдаёт один `warpoint.ru` для Екатеринбурга и Минска; текущая логика выбирает Екатеринбург до исправления доменов в ERP.

## 5. Контент и заявки

Каталог содержит семь игр, для которых в проекте есть данные и изображения. Новые игры добавляйте только с подтверждёнными названием, описанием, параметрами и обложкой. Счётчик каталога строится из реального списка.

Тарифы арены, ВР-станции и зоны экстрим взяты из переданных макетов. Для симуляторов и комбо данные пока не предоставлены. Праздничные тарифы существуют и на страницах мероприятий. Когда появится единый источник тарифов из ERP, перенесите эти данные в один слой, чтобы цены не расходились между страницами.

**Прямая отправка заявок ещё не подключена.** Формы каталога и тарифов создают письмо в почтовой программе посетителя. Формы мероприятий создают клиентские события для будущей интеграции. Пользователь предоставит контракт API заявок и остальные юридические тексты позднее. Политика конфиденциальности находится на `/legal/privacy/`; её текущая копия взята с официального сайта WARPOINT 30 октября 2026 года. После получения данных нужно подключить отправку, обработку ошибок и остальные юридические страницы `/legal/*`, на которые уже ведут ссылки в формах и подвале.

## 6. Проверка каждого изменения

1. Запустите `npm run build` из корня: сборка должна пройти без ошибок.
2. Откройте изменённые страницы на широком экране и на мобильной ширине около 390 px. Проверьте шапку, карточки, формы и отсутствие горизонтальной прокрутки.
3. Пройдите интерактив вручную: вкладки тарифов, фильтры игр, модалки, ссылки, клавиатурный фокус и закрытие по Escape.
4. Проверьте страницу хотя бы на одном другом домене через `PREVIEW_SITE_HOST`: город и canonical должны соответствовать хосту, а неподтверждённые цены не должны появляться.
5. Если добавлен маршрут, проверьте его title, description, canonical и sitemap.

## 7. Очерёдность следующей работы

1. Вести изменения Next.js в отдельном Git-репозитории этой папки. Классическую вёрстку и её историю вести отдельно в `D:\projects\warpoint`.
2. Получить от ERP контракт на игры, тарифы и заявки: поля, идентификаторы, цены по городам, доступность зон, ошибки и способы бронирования.
3. Подключить настоящую отправку заявок и перенести остальные юридические страницы.
4. Исправить неоднозначные домены в ERP и согласовать поведение сайта, когда API недоступен.
5. Дозаполнить каталог и неподтверждённые вкладки тарифов реальным контентом, затем провести мобильную, доступностную и SEO-проверку перед выпуском.

## Стиль новых страниц

Правила компонентов, BEM и SCSS описаны в [CODE_STYLE.md](CODE_STYLE.md). Проверка форматирования новых страниц: `npm run format:pages:check`; исправление: `npm run format:pages`. Статья разделена на `ArticleDetail`, `ArticleHero`, `BirthdayArticleContent` и данные в `lib/article-details.js`. Карточки и окна подробностей каталога, тарифов, акций и анонсов имеют отдельные компоненты. SCSS подключается по блокам из `styles/main.scss`.

## Валидация форм

Правила и тексты ошибок находятся в `lib/form-validation.js`; разбор и форматирование телефонов — в `lib/phone.js`. Компоненты используют `useFormValidation` и `FormError`: ошибка появляется под полем после blur или попытки отправки и обновляется при исправлении. Невалидная форма фокусирует первое поле с ошибкой. Для контейнера формы добавляем класс `form-validation`, для элементов — `validation.fieldProps(...)`; браузерные всплывающие подсказки не используем.

Общие правила: имя от 2 до 100 символов, полный телефон выбранной страны, корректный email (обязательность задаётся каждой формой), обязательное согласие, дата не раньше текущего дня. Не проверяем существование телефона, расписание или сертификат без API. `npm run test:validation` проверяет правила и крайние случаи. При подключении API эти же ограничения нужно проверять на сервере.

## Полосы прокрутки

Общий стиль скроллбаров задаётся в `styles/base/_scrollbar.scss`: размер 8 px, тёмная дорожка и серый скруглённый ползунок. Для новых прокручиваемых блоков достаточно `overflow: auto`; отдельные цвета и размеры скроллбаров в компоненты не добавляем. Горизонтальные полосы с управлением свайпом сохраняют скрытый скроллбар. У статьи прокручивается только текстовая часть; изображение и нижние кнопки остаются на месте.

## Выбранная локация

Выбор общий для страниц: SiteLocationProvider хранит его в cookie warpoint-location на 180 дней. В cookie сохраняются хост, город, название и адрес парка; перестановка арен ERP не меняет выбор, удалённая локация сбрасывается. Первая арена автоматически не выбирается. Телефон, мессенджеры и коммерческие цены скрыты до выбора. На /tariffs сначала выводится приглашение выбрать парк.

ProgramPicker и EventModal используют этот же выбор. useFormValidation добавляет locationId в FormData остальных форм; формы обратного звонка передают событие для будущего API. Общий попап заявки содержит имя, телефон и согласие без онлайн-регистрации. HomeContacts сохраняет исходную карточку главной с выпадающим выбором локации, адресом, расписанием и парковкой; выбор синхронизируется через SiteLocationProvider. Contacts используется на /contacts и страницах мероприятий; на странице контактов всегда видны все парки города.

Каталог разбит по 8 игр без вымышленных карточек. Статьи открываются по прямой ссылке; у материалов без переданного полного текста пока нет активного перехода. Проверки выбора локации, пагинации и размещения точек карты: npm run test:site.
